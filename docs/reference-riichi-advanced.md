# Reference: riichi_advanced — Normal Riichi + Sakicards v1.3

Source tree: `reference/riichi_advanced/`.
This repo contains ~30 rulesets; per request only two are covered here:

- Normal Riichi: `documentation/riichi.md` + `priv/static/rulesets/riichi.majs` + `priv/static/mods/lib/*.majs`
- Sakicards v1.3: `priv/static/rulesets/saki.json` + `priv/static/mods/saki/*.jq` + `lib/riichi_advanced/game/game_state/saki.ex`

## 1. What riichi_advanced is (engine in 5 parts)

From `README.md:129-139`: five moving parts.

1. **MahjongScript (majs) DSL** — rulesets are programs, not JSON blobs.
   Compiler: `lib/riichi_advanced/majs/compiler.ex`. Validator lists every
   legal action/condition (`lib/riichi_advanced/majs/validator.ex:10-16`).
   Docs: `documentation/mahjongscript.md`, `documentation/documentation.md`.
2. **Elixir game state machine** — `lib/riichi_advanced/game/game_state.ex`
   plus submodules (`actions.ex`, `buttons.ex`, `conditions.ex`, `kyoku.ex`,
   `scoring.ex`, `payment.ex`, `marking.ex`, `saki.ex`, `american.ex` …).
   Supervision: `Application -> GameSessionSupervisor -> GameSupervisor ->
   GameState` (`lib/riichiadvanced/application.ex`).
3. **Rust matcher** — hot-loop `match` (tenpai/win decomposition) rewritten in
   Rust: `native/riichiadvanced_match/src`.
4. **Z3 joker solver** — custom rules/jokers compiled to SMTLIB2, solved via Z3
   to enumerate joker assignments: `lib/riichi_advanced/game/smt.ex`,
   `joker_solver.ex`.
5. **In-memory deploy + fault tolerance** — no DB; blue-green cutover pushes
   live games to the fresh server (`lib/riichiadvanced/admin.ex`).

Ruleset formats: new `.majs` (e.g. `priv/static/rulesets/riichi.majs`) and
legacy `.json` (e.g. `priv/static/rulesets/saki.json`). Mods live in
`priv/static/mods/` (`.majs` for rules, `.jq` for tiny deck patches).
Rule tabs shown in-client are generated by `add_rule_tab`/`add_rule` calls
inside the majs files.

### 2.2 Tiles, wall, deal

- 34 kinds, 4 copies each = 136 tiles (`documentation/riichi.md:3-11`,
  `standard_wall.majs:1-34`). One `5m/5p/5s` each is a red five
  (`0m/0p/0s`), worth 1 han as aka dora (`documentation/riichi.md:91`).
- Notation: `1m–9m`, `1p–9p`, `1s–9s`, `1z–4z` winds, `5z–7z` dragons.
- `riichi.majs:114-118`: 13 starting tiles, 14-tile dead wall,
  8 max rounds (East + South), 25000 start.
- Dealer (East) gets a 14th tile; play proceeds counterclockwise with
  draw → discard (`documentation/riichi.md:23`).
- Engine skeleton (`base.majs:45-57`): `after_turn_change` triggers
  ryuukyoku when no tiles remain, else `draw` when `can_draw_condition`.

### 2.3 Win shapes, tenpai, calls

- Win = 4 sets + pair; 7 pairs; 13-orphans (+14th copy)
  (`documentation/riichi.md:13-19`, `standard_win.majs:3-14`).
- Set = sequence or triplet; quads count as triplets for shape purposes.
- Tenpai = one tile away; UI shows waits on hover
  (`documentation/riichi.md:27`).
- Buttons (`riichi.majs:49-110`):
  - `chii`: kamicha discard only, patterns `[[-2,-1],[-1,1],[1,2]]`,
    then `change_turn("self")`. Precedence: pon > chii.
  - `pon`: any discard, pattern `[[0,0]]`, changes turn to caller.
  - `ron`: `someone_else_just_discarded + status_missing("furiten") +
    tenpai + win-with-last_discard`; precedence over chii/pon; does
    `reveal_hand` + `win_by_discard("ron")`.
  - `tsumo`: `our_turn + has_draw + tenpai + win-with-draw` →
    `win_by_draw("tsumo")`.
- Open hand (any chii/pon/kan call) forbids riichi; calls also kill ippatsu
  (`documentation/riichi.md:62-65`).
- Yakuhai: dragon triplets always 1 han; wind triplet if round or seat wind
  (`documentation/riichi.md:67`).

### 2.4 Riichi, ippatsu, furiten

- Riichi: bet 1000, lock hand (all subsequent draws discarded), worth 1 han.
  Every hand needs ≥1 han, so riichi is the most common yaku (~41%)
  (`documentation/riichi.md:29`).
- Cannot riichi with <1000 pts, insufficient wall left, or an open hand
  (`documentation/riichi.md:33-35`). `riichi.majs` gates via `has_draw`,
  `next_draw_possible`, `has_no_call_named`, tenpai match (same pattern reused
  for the saki inazuma variant at `saki.json:1831-1845`).
- Ippatsu: win before your next discard with no intervening calls, +1 han
  (`documentation/riichi.md:31`).
- Furiten (`documentation/riichi.md:37-53`, `lib/furiten.majs:1-33`):
  - Discard furiten: any winning tile in your discards (incl. called tiles)
    → no ron at all, tsumo still allowed.
  - Temp furiten: passed a completable discard → no ron until next draw
    (`discard_passed` sets `furiten` on anyone matching win with last_discard,
    `furiten.majs:26-33`).
  - Permanent (riichi) furiten: riichi passer cannot ron for the round.
  - Cleared on turn/call change unless in riichi
    (`furiten.majs:10-24`).

### 2.5 Dora, kan, ura

- Dora indicator → next tile in sequence (`documentation/riichi.md:85`);
  1 han each but **not yaku** (`documentation/riichi.md:87`).
- Ura: tile under each indicator; only riichi winners access it
  (`documentation/riichi.md:89`).
- Three kan types (`documentation/riichi.md:101-105`):
  - Daiminkan (call discard with triplet), shominkan/kakan (add 4th to own pon),
    ankan (4 in hand, keeps hand closed, dora flips immediately instead of
    after discard).
- Each kan reveals a new dora (and ura) indicator; max 4 kans → 5 indicators;
  the 4th kan ends the game as an abortive draw in this doc's telling
  (`documentation/riichi.md:95-97`). Tunables: `dora`, `ura`, `aka`,
  `kandora`, `immediate_kan_dora` (`riichi.majs:226-234`).

### 2.6 Yaku, fu, scoring (summary)

- Common six (`documentation/riichi.md:109-118`): yakuhai, riichi, tsumo
  (closed only), tanyao (2–8 only), pinfu (closed all-sequence + non-yakuhai
  pair + ryanmen wait), ippatsu. Full list with frequencies at
  `documentation/riichi.md:186-217`; yakuman/double-yakuman at `:219-238`.
- Scoring table (`documentation/riichi.md:126-140`): 1h 1000 (1500 dealer) →
  5h mangan 8000/12000 → haneman → baiman → sanbaiman → 13+h yakuman
  32000/48000; +300/honba + all riichi sticks on the table.
- Payment (`documentation/riichi.md:142-147`): ron = discarder pays all;
  dealer tsumo split equally (rounded up); non-dealer tsumo = ½ dealer +
  ¼ + ¼ (rounded up); multi-ron pays separately, honba/sticks to the closest
  in turn order.
- Fu (`riichi_scoring.majs:1-65`, `documentation/riichi.md:149-176`):
  start 20; sequences 0; triplets 2/4/8 (×4 for kans); tsumo +2; closed ron
  +10; yakuhai pair +2 (+4 double wind); single wait +2; round up to 10;
  chiitoitsu flat 25; closed pinfu-tsumo stays 20; open minimum 30.
  Below mangan: `fu × 4 × 2^han` (×4 dealer, ×6 oya… see doc), round up to 100.
- Pao (`documentation/riichi.md:240-251`, `riichi.majs:177`): dealing the
  final dragon/wind completing daisangen/daisuushii marks you responsible —
  full yakuman on their tsumo, half on others' ron.

### 2.7 Round/match end, exhaustive draw, mods

- East 4 + South 4; dealer repeats on win (renchan: `change_dealership +
  add_honba`, else clear honba — `renchan.majs:1-10`); bust-out below 0 ends
  the game; sudden-death West extension is documented but unimplemented
  (`documentation/riichi.md:178-185`).
- Dead wall = last 14 tiles; exhaustion with only dead wall left = draw
  (`documentation/riichi.md:71`).
- Tenpai payments: 3000 total split among non-tenpai (0/4 tenpai → nothing);
  honba +1 on draws and dealer wins, reset on non-dealer win
  (`documentation/riichi.md:73-81`, `riichi.majs:135`).
- Base `riichi.majs:136-139` defaults: kuikae-ari, **no abortive draws**,
  multi-ron allowed. Everything else (suufon/suucha/suukaikan/sanchahou,
  kyuushu, tobi, uma/oka, agariyame/tenpaiyame, sudden death, min-han,
  kiriage, pao variants, wareme/aotenjou, open riichi, head-bump…) is an
  opt-in `define_mod` (`riichi.majs:157-250+`).

### 3.2 Base table (same skeleton, different constants)

- Same 136 wall with aka (`saki.json:169-202`), plus
  `reserved_tiles: kandraw_1..4` (`saki.json:203-206`).
- Explicit `dora_indicators` / `reverse_dora_indicators` maps
  (`saki.json:208-285`); `max_revealed_tiles: 5` (`saki.json:286`).
- `set_definitions`: pair/shuntsu/koutsu/quad, ryanmen-kanchan shapes,
  ittsuu/sanshoku families, named winds/dragons, junchan sets, 13 orphan
  rotations, chuurenpoutou (`saki.json:287-345`).
- `tenpai_definition` is exhaustive-shape based (`saki.json:346+`).
- Scoring block (`saki.json:884-908`): yaku lists incl. `meta_yaku_2`,
  pao only for Daisangen/Daisuushii, tenpai payments `[1000,1500,3000]`,
  nagashi `[2000,4000]`, oya/ko split, agarirenchan + tenpairenchan,
  riichi 1000, honba base unit `100` (which evaluates via `scoring_old.ex:308,332`
  to standard 300 on ron and 100/payer on tsumo).
- So: same riichi game underneath (draw/discard/calls/furiten/dora/ura/kan),
  with standard riichi scoring and a JSON-driven hook layer for powers.

### 3.3 Draft: how a card enters the game

1. `after_start` (`saki.json:1401-1415`): set `discards_empty` + `nagashi`
   statuses, aka tile aliases (`0m→5m` etc.), placement tags, and if cards are
   not all drafted, `set_status_all "drafting" "match_start"`. East does the
   first `uninterruptible_draw`.
2. `buttons.draft` (`saki.json:1714-1723`): visible while `drafting`;
   `draft_saki_card 4` deals 4 choices, `unskippable`. When nobody is left
   drafting → `saki_start`.
3. `Saki` module (`saki.ex:74-143`): validates `saki_ver` (`v12/v13`) and
   `saki_deck`, shuffles the deck, slices N cards per player
   (`draw_saki_cards`), stores choice as a player `status`
   (`draft_saki_card`), `check_if_all_drafted` gates start, `saki_start`
   fires each seat's `after_saki_start` event.
4. `after_saki_start` (`saki.json:1416-1444`): per-card setup triggers, e.g.
   Saki aliases `1z/2z/4z` in hand to `3z`; Teru sets
   `multiply_honba_with_han`; Kaori/Mase reorder tile sort; Mihoko reveals
   others' hands when 4th; then `unset_status_all "match_start"`.
5. Variants: `persistent_saki_cards` (keep one card all game),
   `two_saki_cards` (draft two; noted unsupported — `saki.json:146-147`).
   Cards can be soft-disabled with a `-disabled` status suffix without
   removing them (`saki.ex:157-184`; used for shimocha/toimen/kamicha locks at
   `saki.json:3261-3318`).

### 3.4 Card model: status + show_when + actions

Every power is a `buttons.<name>` entry with the same shape:

```json
"<key>": {
  "display_name": "...",
  "show_when": ["all_saki_cards_drafted", <status/turn/wind/hand conditions>],
  "actions": [["big_text", ...], ["mark", ...], ["swap_tiles"/"draw"/"set_status"/...]],
  "unskippable": true   // for forced triggers
}
```

Core verbs seen in the sampled cards: `mark` (select tiles),
`swap_tiles` / `move_tiles` (hand ↔ pond / dora indicator / revealed tiles),
`extend_live_wall_with_marked` / `extend_dead_wall_with_marked` (mulligan),
`draw` / `draw_aside` / `draw_from_aside`, `set_status`/`unset_status`
(state flags incl. `riichi`, `ippatsu`, `furiten`, `tenpai`),
`set_tile_alias` / `clear_tile_aliases` (wildcards, aka folding),
`add_counter`/`multiply_counter` (dora/han payments),
`reveal_tile`, `add_honba`, `put_down_riichi_stick`,
`abortive_draw`, `advance_turn`, `recalculate_buttons`
(let tsumo/ron pop up mid-resolution).

Representative buttons (all under `saki.json:1713+`):

- Atarashi Ako — swap a just-called discard (or a dora indicator) with a
  same-suit hand tile; interruptible via `about_to_swap`/`swap_interrupted`
  (`saki.json:1724-1761`).
- Choe Myeonghwa — swap a terminal/honor in hand with the last discard when
  it matches your seat or round wind (`saki.json:1762-1821`).
- Haramura Nodoka — once-per-game facedown discard
  (`haramura-nodoka_exhausted + discard_facedown`, `saki.json:1822-1830`).
- Ikeda Kana — Inazuma Riichi: 5000-pt riichi with immediate stick(s);
  all-riichi → Suucha Riichi abort (`saki.json:1831-1862`).
- Kataoka Yuuki — East-only mulligan: mark 4 hand tiles, append to live wall
  end (last = haitei), draw 4; once per game
  (`saki.json:1863-1875`).
- Matano Seiko — set aside the discarded 4th copy of a pon tile (plus Skip)
  (`saki.json:1876-1894`).
- Nanpo Kazue — South-only: put 2 hand tiles at dead-wall end, draw 2
  (last = first kan draw); a second trigger fires off pond size
  (`saki.json:1895-1931`).
- Onjouji Toki — draw an extra tile aside, later choose aside-draw vs
  wall-draw, then swap (`saki.json:1932-1965+`).

Passive/scoring hooks (no button press):

- `extra_yaku` entries gated on `status: <card>` — e.g. Mako closed-bonus han
  for Chanta/Ittsuu/Sanshoku/… (`saki.json:545-556`), Nodoka closed
  Tanyao/Pinfu (`saki.json:558-559`), Hisa "Single Wait" 2 han at ≤1 wait
  (`saki.json:648`).
- `before_win` (`saki.json:1445-1701`): reveal pending kan-dora, grant Momoko
  riichi+ura when closed, count dora/aka/ura from revealed tiles, double them
  for Kuro (zero them if `matsumi_kuro_dora_disabled`, set when Kuro discards
  dora outside riichi — `saki.json:1396-1398,1553-1564`), Saki rinshan
  wildcard + Koromo haitei wildcard via `set_tile_alias … ["any"]`
  (`saki.json:1674-1677`), per-card han counters (Mase, Matano, Yuu, Arata,
  Kajiki, Ueshige, Suehara, Hatsumi, Iwato, …).
- Turn hooks: `before_turn_change` handles Suucha Riichi, ippatsu clearing,
  riichi-stick payment, stepwise kan-dora reveal, furiten reset, placement
  tags (`saki.json:926-999`); `before_call` re-clears ippatsu, takes the
  riichi stick on `just_reached`, reveals kan-dora, refreshes tenpai
  (`saki.json:1122-1143`); `after_call` sets furiten on win-matching calls,
  assigns pao responsibility for dragon/wind yakuman calls, Teri honba,
  Mako extra turn on green calls (`saki.json:1144-1234`); `after_draw`
  tags `rinshan`/`haitei` attrs (`saki.json:1235-1238+`).
- `play_restrictions` (`saki.json:909-925`): global gates — no discards before
  draft; riichi/iishanten lock-ins; kuikae (`last_called_tile_matches kuikae`
  unless Toyone); Koromo discard lock; facedown-discard and scry locks.

### 3.5 How to read a new card

1. Find its `buttons.*` block(s) in `saki.json` (search the card slug).
2. Read `show_when`: whose turn, which statuses must (not) be set, wind/seat,
   hand shape (`tenpai`, `has_draw`, score thresholds).
3. Read `actions` in order; `mark` selections + `swap/move/draw/alias`
   effects are the whole mechanic.
4. Check `after_saki_start`, `before_win`, and hook sections for passive parts
   (aliases, counters, extra yaku).
5. Card identity at runtime is just a string in `player.status`
  (`saki.ex:141-143`); `filter_cards`/`disable_saki_card` manage the `-disabled`
  variant. There is no per-card code file — behavior is data in `saki.json`.
